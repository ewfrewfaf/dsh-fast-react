# 快速反应（dsh-fast-react）使用须知

> 面向使用者与二次开发者：装什么、怎么用、接口怎么调、出问题怎么查。
> 原理见 [技术路线](./技术路线.md)。

---

## 1. 安装

### 1.1 前置

| 项 | 要求 |
|---|---|
| DeepSeek Harness | 桌面版或 `dsh web`（插件依赖 `webserver` / `agentLoop` / `agentPresets` 服务） |
| Node.js | ≥ 20 |
| 模型 | 至少一个可用 provider（面板里可切换） |

### 1.2 从 tgz 安装（推荐，离线可用）

```bash
# 在 DSH 安装目录或任意终端，指向你下载的包
dsh plugin --profile <你的 profile> add /path/to/dsh-fast-react-<版本>.tgz
```

安装后**重启 DSH**（首次装配需要），然后：

- 侧边栏「插件」下方会多出 **快速反应** 入口
- 或直接访问控制台：`http://127.0.0.1:<DSH web 端口>/fr`（默认常见 19387）

### 1.3 从源码链接（开发者）

```bash
# profile 的 package.json dependencies 里加：
"dsh-fast-react": "link:C:/path/to/dsh-fast-react"
# 并把 "dsh-fast-react" 加进 dsh.profile.bundles
```

> 改 `lib/ui/*` 不需要重启：loader 每 3s 拉取并注入（首次需重启以装配插件）。
> 改 `lib/index.js` / `lib/api.js`（后端）需要重载插件或重启 DSH；**正在跑任务时不要重载，会销毁内存会话**。

## 2. 五分钟上手

1. 打开面板（侧边栏「快速反应」或 `/fr`）
2. 右上角 **启动** → 前后台接线完成（首次会自动创建两个会话）
3. 输入栏直接打字，`Enter` 发送
4. 简单任务：前台自己干完就回；复杂任务：前台上交后台，后台写 `steps/S1.md` 后自动推进
5. 想介入随时发消息：
   - **开关关（默认）** = 消息排队，等当前这步结束处理
   - **开关开（发送即打断）** = 先 cancel 当前生成，立刻处理你的新消息

### 关键按钮

| 控件 | 作用 |
|---|---|
| 启动 / 停止 | 启用/暂停整套编排（T3 拦截、实时投递、30s 巡检）。不销毁会话 |
| ⊞ 会话组管理 | FR-01… 新建/收编/删除/切换/自愈；每组可单独设权限 |
| ⚙ 技术面板 | 任务进度、步骤、路线检查、效率指标、唤醒分布、事件流 |
| 模型 ▾（输入栏右下） | 切换前后台使用的模型（20+ provider） |
| 发送即打断（开关） | 见上 |

## 3. 会话组（推荐用法）

- **编号规则**：`FR-01 / FR-02 …` 由服务端生成，**界面不可改**；客户端传 `key` 会被忽略（防改号）
- 每组 = 前台 `FR-0x·F` + 后台 `FR-0x·B`，全部 attach 并 pin 到「快速反应」工作区 ⇒ 可在 DSH 侧边栏直接打开原生会话页
- **收编当前**：把已经在跑的前后台直接登记成一个组（不新建会话）
- **自愈**：编号重排、丢失会话重建、工作区重新挂载、权限重新应用
- **权限**：每组一个下拉（`read-only` / `workspace-write` / `danger-full-access` / `auto`），选完立即写入沙箱模式 + 审批策略（复用 DSH `permissionPresets`）
- 新建默认权限：管理面板里的「新建默认：…」（写 `cfg.permissionPreset`，20s 内也会校正当前前后台）

> 权限被拒时前台会回一行 `【上报·权限】缺 …` 并停下，不会无声重试。

## 4. 预留 API（二次开发）

所有接口都在你的 DSH Web 地址下（下文示例统一用 `http://127.0.0.1:19387`，请替换成 `dsh web` 打印的端口），`Content-Type: application/json`。

### 4.1 状态

```bash
GET /fr/api/status
```

返回（节选）：

```json
{
  "front": {"id":"session-fr-01-front-…","phase":"idle"},
  "back":  {"id":"session-fr-01-back-…","phase":"idle"},
  "state": {"planVersion":"1","status":"working","done":"S2"},
  "steps": ["S1.md","S2.md"],
  "chat":  {"front":[{"at":"…","role":"user|agent|notice","text":"…","think":"…"}], "back":[]},
  "models": {"provider":"deepseek-account","model":"deepseek-flash"},
  "permissions": {"front":"danger-full-access","back":"danger-full-access","default":""},
  "stall": {"watchdog":true,"timeoutMs":150000},
  "metrics": {}, "recent": []
}
```

### 4.2 发任务（最常用）

```bash
curl -X POST http://127.0.0.1:19387/fr/api/task \
  -H 'content-type: application/json' \
  -d '{"text":"把 README 里的示例命令跑一遍并汇报","interrupt":false}'
```

- `interrupt:false`（默认）= 排队到下一步
- `interrupt:true` = 先 cancel 当前生成再投递（返回 `{"mode":"interrupt","cancelled":true}`）

**会话寻址（v1.0.1）**：默认目标是当前接线的前台，但可以精确指定任意会话：

```bash
# 1) 按会话 id（可从 /fr/api/sessions 查）
-d '{"text":"…","sessionId":"session-fr-back-abc123"}'

# 2) 按会话组 + 角色（front / back）
-d '{"text":"…","group":"FR-01","role":"back"}'

# 3) 按角色（当前接线的后台）
-d '{"text":"…","role":"back"}'
```

返回带 `session` 字段说明实际投递到了哪个会话：

```json
{"ok":true,"session":"session-fr-01-front-…","mode":"wake","interrupt":false,"cancelled":false}
```

### 4.2.1 会话清单与单会话信息

```bash
GET /fr/api/sessions
```

```json
{"sessions":[
  {"id":"session-fr-front-…","role":"front","phase":"idle","cwd":"…","preset":"workspace-write","group":"FR-01·F","wired":true},
  {"id":"session-…","role":"other","phase":"running","cwd":"…","preset":"danger-full-access","group":"","wired":false}
]}
```

> `role` 为 `other` 的是非本插件接管的会话（例如你当前正在用的那个），**同样可以被寻址投递**。

```bash
GET /fr/api/session?id=<sessionId>
GET /fr/api/session?group=FR-01&role=front
GET /fr/api/session?role=back
```

### 4.3 启停 / 重建 / 打断

```bash
POST /fr/api/start     # {"ok":true,"front":true,"back":true}
POST /fr/api/stop      # {"front":true,"back":false}
POST /fr/api/rebuild   # 重建前后台会话（丢弃内存态）
POST /fr/api/fire      # {"reason":"手动打断"}  ← 与 interrupt 不同：只打断，不投递
```

`fire` 也支持会话寻址（直接 cancel 目标会话，不走全局冷却）：

```bash
POST /fr/api/fire -d '{"reason":"停","sessionId":"session-…"}'
POST /fr/api/fire -d '{"reason":"停","group":"FR-01","role":"back"}'
```

### 4.4 配置

```bash
GET  /fr/api/config
POST /fr/api/config  -d '{"batchSteps":3,"stallTimeoutMs":150000,"permissionPreset":"danger-full-access"}'
```

可写字段：`batchSteps` `frontContextLimit` `backContextLimit` `pullSteps` `contextGuard` `enabled`
`lookahead` `interruptCooldownMs` `interruptMaxPerTask` `sentinelIntervalMs`
`stallWatchdog` `stallTimeoutMs` `stallSafeRetry` `linkWorkspaceSession` `permissionPreset`

### 4.5 模型

```bash
GET  /fr/api/models                 # {"providers":[{"provider":"deepseek-account","models":["deepseek-flash",…]}],"current":{…}}
POST /fr/api/model  -d '{"provider":"deepseek-account","model":"deepseek-flash"}'
```

### 4.6 会话组

```bash
GET  /fr/api/groups
POST /fr/api/groups -d '{"action":"create","title":"桌面整理"}'      # 新建
POST /fr/api/groups -d '{"action":"create","adopt":true}'           # 收编当前前后台
POST /fr/api/groups -d '{"action":"switch","key":"FR-01"}'          # 切换
POST /fr/api/groups -d '{"action":"policy","key":"FR-01","preset":"danger-full-access"}'
POST /fr/api/groups -d '{"action":"repair"}'                        # 自愈
POST /fr/api/groups -d '{"action":"delete","key":"FR-02","force":true}'
```

### 4.7 事件 / 中继

```bash
GET  /fr/api/events?since=2026-10-17T12:00:00Z&limit=50
POST /fr/api/relay -d '{"action":"wake","args":{"text":"继续"}}'     # 等价 fr_poke 的 HTTP 版
```

`relay` 支持 `wake` / `steer` / `fire` / `config`；更全的运维动作走插件工具 `fr_poke`（前台禁止调用）。

### 4.8 侧边栏脚本（热更新通道）

```bash
GET /fr/sidebar.js      # 返回注入脚本；改这个文件 3 秒内自动生效（无需重启）
```

## 5. 文件与黑板

```
<工作目录>/.board/
├── config.json      # 运行配置
├── groups.json      # 会话组注册表（FR-0x → 前后台 sessionId + preset）
├── state.md         # planVersion / status / done
├── route.md         # 后台写的路线（含「## 里程碑」「## 哨兵条件」段）
├── steps/S1.md…     # 步骤文件（前台自取）
├── handoff.md       # 前台上交
├── confirm/         # T3 放行令牌（S<k>.ok）
├── heartbeat.log    # 每次工具执行一行
└── events.jsonl     # 全部事件（排障第一现场）
```

## 6. 排障

| 症状 | 先看 | 处理 |
|---|---|---|
| 面板没反应 | `/fr/api/status` 的 `front` 是否为 null | 点「启动」或 `POST /fr/api/start` |
| 消息发了但没动作 | `phase` 是 running 还是 idle；`config.enabled` | 打开「发送即打断」重发 |
| 长时间空白 | `stall`（150s 看门狗）+ `heartbeat.log` 末行 | 看门狗会自动 cancel；仍未恢复就点「停止」再「启动」 |
| 卡在确认 | `.board/confirm/` 是否有令牌；面板是否有琥珀色通知 | 写入 `<step>.ok` 放行 |
| 权限被拒 | 面板权限 chip / 会话组权限下拉 | 改成 `danger-full-access` |
| 侧边栏看不到会话 | 会话组管理里的状态点是否 `missing` | 点「自愈」 |
| UI 改了不生效 | loader 是否在跑（浏览器 console 有无 `/fr/sidebar.js` 请求） | 重启 DSH 一次后即可热更新 |

## 7. 与其它插件共存（可选）

- 本插件**不依赖任何记忆类插件**，单独安装即可工作。
- 与记忆 / 审计 / 监控类插件**不冲突**：它只读写自己工作目录下的 `.board/`，不改动 DSH 的 DOM 与全局配置（面板是纯浮层）。
- 会话内容本身由 DSH 会话日志保存；如需「跨会话长期记忆」，请安装你信任的记忆插件，并按**它的官方文档**配置模型与存储位置。
- 若某个插件也注入侧边栏或覆盖会话区，可能与面板视觉叠加 —— 先禁用它做对照，再决定是否调整。

---

## 8. 已知限制

1. **热重载会销毁内存会话**（含排队消息）—— 任务运行中别重载。
2. 面板覆盖原生会话区，**会盖住右下角挂件/浮层**（当前设计取舍）。
3. 后台首帧通常 **30–60s**（高档模型），属正常；面板会显示运行指示。
4. T3 闸门只覆盖 `pwsh`/`bash` 明确危险模式，非穷举。
5. 权限预设来自 DSH 的 `permissionPresets` 目录，不同版本选项可能不同（面板会自动列出）。
6. 会话是**内存态**：DSH 重启后需要重新「启动」接线；黑板文件仍在，状态可重建。

## 附录 B：常见自定义

| 想改什么 | 怎么改 |
|---|---|
| 端口 / 访问地址 | 由 DSH 决定，本插件跟随；不要单独给插件起服务器 |
| 安装到别的 profile | 把命令里的 `--profile desktop` 换成你的 profile 名 |
| 面板权限 | 会话组管理 → 每组权限下拉（`danger-full-access` 可免审批） |
| 卡死判定时长 | `POST /fr/api/config -d '{"stallTimeoutMs":150000}'`（毫秒） |
| 关掉工作区自动挂载 | `POST /fr/api/config -d '{"linkWorkspaceSession":false}'` |
| 关掉僵死看门狗 | `POST /fr/api/config -d '{"stallWatchdog":false}'` |
