# 升级 DSH 后的兼容性验证（快速反应）

> 目的：DSH 升级（如 `0.2.0-rc.2 → 0.2.1-rc.1`）可能改动内部接口，导致插件部分功能静默失效。
> 本文提供**升级前备份 → 升级 → 逐项验证 → 失效修复**的完整流程，全程约 10 分钟。

---

## 0. 插件依赖了 DSH 的哪些内部接口

| 依赖 | 用途 | 失效表现 |
|---|---|---|
| `webserver/index-inject` | 注入侧边栏按钮与脚本 | 侧边栏没有「快速反应」入口 |
| `agentLoop.create` + `agentPresets.mount` | 创建会话组、挂 `standard` 预设 | 会话组「新建」失败 |
| `agent/turn-stopping`、`agent/pre-step` | 实时投递下一步、T3 破坏性闸门 | 步骤不推进 / 拦截失效 |
| `permissionPresets.set` | 会话组权限（沙箱+审批） | 权限下拉选完不生效 |
| `workspaceRegistry.attachSession / pinSession` | 把前后台挂进「快速反应」工作区 | DSH 侧边栏看不到会话 |
| `approval` / `tokenMeter` / `compaction` | 审批策略、上下文守护 | 权限不生效 / 压缩失效 |
| 会话事件（`user/message`、`assistant/message`、`reasoning` 块） | 面板对话与思考折叠 | 面板无消息或思考不显示 |
| `ctx.agents.list / get` | 会话清单、会话级 API | `/fr/api/sessions` 为空 |

## 1. 升级前：备份 + 建基线

```powershell
# ① 备份 profile（配置、装配、patch）
$ts = Get-Date -Format 'yyyyMMdd-HHmmss'
Copy-Item "$env:USERPROFILE\.dsh\profiles\desktop" -Destination "$env:USERPROFILE\.dsh\profiles\_backup-$ts" -Recurse

# ② 备份插件目录（如果用的是 link 安装，源码本来就在，可跳过）
# ③ 记录当前 DSH 版本
(Get-Process | Where-Object { $_.ProcessName -match 'DeepSeek' } | Select-Object -First 1).MainModule.FileVersionInfo.FileVersion
```

**建自检基线**（在插件源码目录执行）：

```bash
node tools/selfcheck.mjs 19387 "D:/备份/升级基线-$(版本).json"
```

> 期望：**18 项全绿**。这份 JSON 就是升级后的对照基准。

---

## 2. 升级

- 桌面端：点左下角 **「新版本」** → 按提示安装 → 重启
- 或直接运行已下载的安装包（`%LOCALAPPDATA%\@deepseek-aidsh-desktop-updater\` 里能看到，如 `deepseek-harness-0.2.1-rc.1-win-x64.exe`）

升级后 DSH 重启，**插件会重新装配**，此时：

1. 看侧边栏有没有「快速反应 1.0」
2. 打开控制台 `http://127.0.0.1:<端口>/fr`

---

## 3. 升级后：跑同一份自检

```bash
node tools/selfcheck.mjs 19387 "D:/备份/升级后-$(版本).json"
```

对照两张表：

| 结果 | 含义 |
|---|---|
| 18/18 通过 | ✅ 完全兼容，无需处理 |
| 个别失败 | 按下表定位（失败项名字对应依赖） |

### 失败项 → 修复方向

| 失败项 | 大概率原因 | 修复 |
|---|---|---|
| `sidebar.js 可访问` | 插件未加载 | 插件面板里确认 `dsh-fast-react` 已启用；或重装插件 |
| `控制台页面可打开` | 路由注册失败 | 重启 DSH；查看 DSH 插件日志 |
| `status 接口` | 插件 apply 抛错 | 看 `.board/events.jsonl` 与 DSH 日志 |
| `models 接口 / ctx.llm` | `ctx.get('llm')` 签名变化 | 需要更新 `lib/index.js` 的 `listModels` |
| `groups 接口 / permissionPresets` | 权限服务改名/改形状 | 更新 `applyPreset` / `permissionCatalog` |
| `sessions 接口 / ctx.agents` | agents 服务变化 | 更新 `listSessions` |
| `前后台接线` | 会话被重建/丢失 | 点「启动」；会话组面板点「自愈」 |

**通用兜底**：`.board/events.jsonl` 的 `plugin-start` 之后若无新事件，说明插件 apply 阶段就挂了 —— 看 DSH 启动日志里的 `fast-react` 报错。

---

## 4. 出问题时的回滚

1. 关闭 DSH
2. 重新安装旧版本安装包（若还在 `%LOCALAPPDATA%\@deepseek-aidsh-desktop-updater\` 里）
3. 若 profile 也被动过：把 `_backup-<时间戳>` 目录改名回 `desktop`

> 插件本身不需要回滚 —— 它不在 DSH 安装目录内，profile 里只是 `link:` 或依赖声明。

---

## 5. 日常建议

- **别用 nightly 通道做主力工作环境**：插件依赖的是内部接口，nightly 变动最快
- 升级前**一定备份 profile**（30 秒，能省几小时）
- 每次升级后**跑一次 selfcheck**，把结果留档，方便下次对照
- 插件里的 `peerDependencies` 已声明 `@deepseek-ai/cordis >=4.0.0-rc <5`，大版本不匹配时安装器会直接拒绝，属于保护而非故障

## 6. 已知坑（DSH 0.2.1 实测）

| 现象 | 根因 | 修复 |
|---|---|---|
| 升级后侧边栏入口消失、/fr 404，loader 里没有 dsh-fast-react | \package.json\ 带 UTF-8 BOM，0.2.1 的严格解析直接判插件无效并静默跳过 | 用 node 重写文件（无 BOM）；**禁止 PowerShell \Set-Content -Encoding UTF8\** |
| 前台"思考强度"变 high、后台未设置（与配置不符） | 0.2.1 起 \gentLoop.create\ **不再自动继承全局 reasoningEffort**，未显式传则各会话取值不一致 | 创建/重建会话时显式传 \easoningEffort\：前台 \cfg.frontEffort\(low)、后台 \cfg.backEffort\(max)；改完 \/fr/api/rebuild\ 一次 |

> 档位合法值：\off / low / medium / high / max\（来自 DSH 的 \REASONING_EFFORTS\ 常量）。

## 7. 免费模型（our-free-model）实测

结论：**完全可用，与付费 API 等价**。此前"免费模型不能用"的观感源于插件自身的会话接管 bug（已修）。

| 项目 | 实测结果 |
|---|---|
| 模型 | `our-free-model/deepseek-v4.1-flash-free`（33 个免费型号可切） |
| 轻任务端到端 | 24s 完成，多文件产出正确，交付正文含结论/路径/注意事项 |
| 上交后台链路 | 前台上交 12s → 后台出路线 18s → 生成 6 步 → 步骤投递成功 |
| 自检 | 18/18 通过（与付费模型一致） |

**注意**：若出现"新建会话收到消息但永不 running"，那是 1.0.9 之前版本的
`wire()` 缺陷（rebuild 只写 overrides 不写 cfg，导致新会话不被接管），
升级到 1.0.9+ 即修复；也可跑 `node tools/verify-wire.mjs <端口>` 复验。
