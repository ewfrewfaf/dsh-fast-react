# 废案：事故守门员（并行版「总监」）

> 状态：**废案（2026-11-06 归档）**，未实现。
> 归档原因：用户判断当前收益不值当，先存着，等有真实事故数据再评估。

---

## 1. 它是怎么被提出来的

原方案（v2）里有个「总监」——三体拆分的第三角色，在定稿 / 里程碑 / 结局三个检查点审阅是否偏航。

**否决理由（保留）**：它插在关键路径上，每次唤醒 ≥15s，每任务 3 次 = **必然 +45s**，而它只在「需求理解错位」时才有价值，这种情况占返工的少数。用必然换偶然，期望值为负。

**用户后来提的改法**：让总监**并行**跑，不占关键路径，定位改成「不追求准确，只防灾难性错误的兜底哨兵」。

这个改法把成本模型从「必然 45s」改成「按需付费」，原来那条 EV 结论不再自动成立，所以重新评估过一次。

---

## 2. 重新评估的结论

成本从「必然墙钟」变成了「token + 误报打断」，但新成本不低：

| 项 | 数值 | 出处 |
|---|---|---|
| 一次打断的代价 | 白扔一次生成，median 11–14s | 实测 |
| 打断预算 | 冷却 60s，每任务 ≤5 次 | `defaults.js` |
| 守门员需要的输入 | 要么短（工具参数，判断弱，误报多）；要么长（全上下文，贵） | — |

关键矛盾：**「不追求准确」的守门员如果误报多，会把打断预算烧光，真出事时反而没额度。**
所以放宽标准必须偏向**漏报**，而不是「宁可错杀」。

---

## 3. 如果将来要做，规格是这一份

核心：**不是并行总监，是两级过滤**——程序层先挡，模型只处理程序层判不了的。

```
tools/post-execute（工具边界，绝不在执行中间打断）
   ↓
L1 程序层（0 成本、纯本地）
   命中危险模式 → 才往下走
   ↓
L2 语义层（一次便宜模型调用，8s 超时）
   只回 allow / pause，无改路线权限
```

### L1 规则表（草案）

| 规则 | 例子 |
|---|---|
| 破坏性命令 | `rm -rf`、`format`、`DROP TABLE`、`git reset --hard`、删 `.git` |
| 越界写入 | 写 `C:\Windows`、`%APPDATA%`、其它项目目录 |
| 批量破坏 | 单步删除/覆盖 > 15 个文件，或单步写入 > 5 MB |
| 凭据风险 | 读 `.credentials.yaml` / `*.env` 后紧接着往外发 |

### L2 契约

| 项 | 决定 |
|---|---|
| 挂点 | `tools/post-execute` |
| 触发 | **仅 L1 命中**；正常任务永不叫模型 |
| 模型 | 便宜模型（buddy/hy3 档），8s 超时，超时静默放弃 |
| 输入 | 最近 3 条工具调用摘要 + 当前步骤目标，**不塞全上下文** |
| 输出 | 只有 `allow` / `pause`；`pause` 只发一句「停一下，说明你在删什么」，**不 cancel** |
| 预算 | 每任务 ≤2 次，冷却 60s |
| 红线 | 不改路线、不规划、不评价质量 |

代码量估计：60–80 行（含规则表），落在 `lib/index.js` 的 post-execute 分支。

---

## 4. 复活条件

| 条件 | 说明 |
|---|---|
| 出现≥1 次真实不可逆事故 | 没有真实伤害数据，触发率调不出来 |
| 或实测「需求理解错位导致的返工」占任务总时间 > 30% | 那时串行总监也重新值得评估 |

**唯一会让这个方案重新变成负期望的做法**：让它开始评价「做得好不好」。
一旦管质量而不只是管灾难，触发率会从「每任务 0~1 次」涨到「每几步一次」，45s 的账就从墙钟变成 token 回来了。

---

## 5. 与现有机制的关系

| 现有机制 | 覆盖的灾难类型 | 与守门员的关系 |
|---|---|---|
| 机械哨兵（只认文件/数值条件） | 心跳停滞、卡死、步骤未就绪 | 已覆盖「机械类」，守门员不重复 |
| 僵死看门狗（150s 无活动） | 模型流卡住 | 已覆盖 |
| T3 闸门 + 权限预设 | 越权操作 | 部分覆盖「越界」，但只在会话级 |
| **守门员（本废案）** | **语义类不可逆破坏**（删错东西、改错文件、外发凭据） | 唯一增量价值 |

换句话说：**它的价值只在「机械规则判不了、但破坏不可逆」这一个夹缝里**。这个夹缝有多大，目前没有数据。
